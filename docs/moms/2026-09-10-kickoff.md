## Discussion Notes

### 1. Project Pitch & SRS Walkthrough
- Jamir presented the project overview and pitched the Software Requirements Specification (SRS) using the presentation deck.
- Covered core problem statements: manual verification friction, campus booth queue bottlenecks, split-brain merchandise releases, and zero-escrow financial model.
- Emphasized core v1 safeguards: atomic booth dispatch terminal, passwordless magic links, reservation TTLs, and automated MOQ safeguards.

### 2. Tech Stack Selection
- Reviewed the architecture proposals from the presentation.
- Evaluated Option 1 (Lean Full-Stack Next.js Monolith) vs Option 2 (Scalable Modular Next.js + Dedicated Services).
- Collectively decided to proceed with **Option 1: Lean Full-Stack Next.js (Free Tier Monolith)**:
  - Framework: Next.js (App Router) on Vercel Free Tier.
  - Database: Supabase (PostgreSQL 500MB Free Tier with RLS and Security Definer functions).
  - Storage: Cloudflare R2 (10GB Free Tier) for receipt screenshots and product mockups.
  - Authentication: Supabase Auth / Resend magic links.
  - Rationale: Zero capital outlay (0 PHP), rapid 6-8 week development velocity, and low operational overhead for the MVP.
